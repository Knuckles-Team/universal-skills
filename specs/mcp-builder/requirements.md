# US-MCP-BUILDER — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `US-MCP-BUILDER-R001` | **Governed HTTP client.** A scaffolded connector must build every HTTP client with `agent_connector_sdk.http.create_http_client`, so SDK retries, 429 handling and egress pinning apply. It must pin neither `requests` nor `httpx` and ship no retry loop. SDK owner: `SDK-CENTRALIZED-CAPABILITIES-R001`, `SDK-CENTRALIZED-CAPABILITIES-R040`. Proving test: `tests/test_mcp_builder_sdk_standard.py::test_http_uses_the_sdk_governed_client_and_pins_no_http_library`. | The scaffolded API client imports the governed client and declares no HTTP library. A planted `requests` import, own `httpx` client, retry policy and `requests` pin are each reported. |
| `US-MCP-BUILDER-R002` | **TLS profile.** A scaffolded connector must resolve TLS with `resolve_tls_profile` and pass the profile to the client. It must never set `verify=False`, silence TLS warnings or build an SSL context. SDK owner: `SDK-CENTRALIZED-CAPABILITIES-R008`. Proving test: `tests/test_mcp_builder_sdk_standard.py::test_tls_comes_from_the_resolved_profile`. | `auth.py` resolves the profile and no generated module disables verification. Planted bypasses are reported. |
| `US-MCP-BUILDER-R003` | **Credential references.** A scaffolded connector must resolve secrets only through the SDK credential support, accepting `env://` and `openbao://` references. It must not parse references by hand or read a token from a plain environment variable. SDK owner: `SDK-CENTRALIZED-CAPABILITIES-R009`. Proving test: `tests/test_mcp_builder_sdk_standard.py::test_secrets_resolve_through_the_sdk`. | `auth.py` passes the `*_TOKEN_REF` setting to `bearer_auth`. A planted hand parser and a plain-environment token read are reported. |
| `US-MCP-BUILDER-R004` | **Optional dependencies through SDK extras.** A scaffolded connector must declare optional dependencies only as `agent-connector-sdk[<extra>]` and must pin no package an SDK extra already pins. A GraphQL connector must use the `graphql` extra and the SDK introspection helpers and pin no `gql`. SDK owner: `SDK-CENTRALIZED-CAPABILITIES-R016`, `SDK-CENTRALIZED-CAPABILITIES-R040`. Proving test: `tests/test_mcp_builder_sdk_standard.py::test_graphql_uses_the_sdk_extra_and_helpers`. | The GraphQL variant depends on `agent-connector-sdk[mcp,graphql]` and imports the SDK helpers. Planted database and `gql` pins are reported. The `vector` extra joins the list when the SDK ships it. |
| `US-MCP-BUILDER-R005` | **Fleet identity declared once.** A scaffolded connector must declare its fleet name once, as the single `agent_connector_sdk.connector` entry point of `SDK-CONNECTOR-CONTROL-R071`. It must build content with `ConnectorContent.for_package` and ingest bindings with `IngestBinding.for_package`, and spell the name in no other source. The manifest and fingerprint files carry the same name. SDK owner: `SDK-CENTRALIZED-CAPABILITIES-R030`. Proving test: `tests/test_mcp_builder_sdk_standard.py::test_fleet_name_is_declared_once_and_never_spelled`. | The entry point, manifest and fingerprints agree and no generated module holds the name. A planted literal binding and a second entry point are reported. `--fleet-name` reaches every declaration. |
| `US-MCP-BUILDER-R006` | **Tool surface, bootstrap, agent contract and specs.** A scaffolded connector must register one tool per API operation through `register_tool_surface`, ship the safe `scripts/bootstrap.sh` with no piped installer, carry the standard `AGENTS.md` agent-contract section, and ship a `specs/` tree per the pipelines spec standard with its tests bound. SDK owner: `SDK-CENTRALIZED-CAPABILITIES-R015`. Proving test: `tests/test_mcp_builder_sdk_standard.py::test_surface_bootstrap_agent_contract_and_specs`. | The scaffold shows each artifact. A planted piped installer and a missing spec file are reported. |
| `US-MCP-BUILDER-R007` | **Version bookkeeping.** A scaffolded connector must list only existing files in `.bumpversion.cfg`, define `__version__` in `_version.py` alone, and track the Dockerfile image version pin through bumpversion at the same version as `pyproject.toml`. Proving test: `tests/test_mcp_builder_sdk_standard.py::test_version_is_single_sourced_and_bumpversion_tracks_every_pin`. | A planted missing file entry, a drifted image pin and a second `__version__` are each reported. |
| `US-MCP-BUILDER-R008` | **Pipelines hooks in strict mode.** A scaffolded connector must enable the pipelines `connector-name` hook and the `sdk-conformance` hook with `args: [--strict]` in its pre-commit config, and run `check-cli-help` from a plain install. Pipelines main does not publish `sdk-conformance` yet, so the scaffold emits it commented out as pending until `SDK_CONFORMANCE_PUBLISHED` flips. Proving test: `tests/test_mcp_builder_sdk_standard.py::test_precommit_enables_the_strict_hooks`. | The config enables `connector-name --strict`, carries the pending `sdk-conformance` strict entry and a plain `check-cli-help`. The flag renders the live entry. A removed hook and a `uv run` entry are reported. |
| `US-MCP-BUILDER-R009` | **Checklist in the skill.** `SKILL.md` must list rules R001 to R008 and R010 with their row IDs and the SDK rows they protect in a section named `SDK conformance checklist`. Proving test: `tests/test_mcp_builder_sdk_standard.py::test_skill_checklist_names_every_rule_and_sdk_row`. | The checklist names every `US-MCP-BUILDER` row and the SDK rows. |
| `US-MCP-BUILDER-R010` | **Ontology linked to the parent, data resources from SDK defaults.** A scaffolded connector must ship a domain ontology that declares `owl:imports <http://knuckles.team/kg>`. Each scaffolded class must extend a core class of the parent ontology with `rdfs:subClassOf`. The scaffold uses `:Concept`, a class in `core-foundation-v1.ttl` of epistemic-graph. The ontology must hold no TODO text. The scaffold must write no data-resource declaration. It requires an SDK release that derives them, `agent-connector-sdk>=0.3.19`, under `SDK-CONNECTOR-CONTROL-R074.7`. A connector adds `data_resources.json` only to override a default. SDK owners: `SDK-CONNECTOR-CONTROL-R073`, `SDK-CONNECTOR-CONTROL-R074.7`. Proving tests: `tests/test_mcp_builder_sdk_standard.py::test_scaffold_links_the_ontology_to_the_parent_without_a_todo` and `tests/test_mcp_builder_sdk_standard.py::test_scaffold_relies_on_sdk_default_resource_declarations`. | The generated ontology imports the parent, and every class extends a core parent class. The contract check reports a missing import, a class without a parent and a TODO. The scaffold ships no `data_resources.json`. The SDK derivation proposes a mapping for the scaffolded class. |
| `US-MCP-BUILDER-R011` | **Connector scaffold on SDK components.** The `scaffold_connector.py` generator must emit only connector-specific files and build the connector on SDK components. Parent of R011.1 to R011.11. SDK owners: `SDK-CONNECTOR-CONTROL-R019.1`, `SDK-QUALITY-RELEASE-R005.1`. Proving test: the tests of the child rows. | Every child row is proven by its test. |
| `US-MCP-BUILDER-R011.1` | **Minimal tree.** The generator must write exactly the 22 files of the minimal connector tree and none of the files the SDK or pipelines own: no `mcp_server.py`, `_version.py`, `.bumpversion.cfg`, `connector_sources.py`, `certification.json`, shapes file, `mcp_config.json`, `conftest.py`, `kg_ingest.py` or `auth.py`. | `tests/test_mcp_builder_connector_scaffold.py::test_scaffold_emits_exactly_the_minimal_tree` passes. |
| `US-MCP-BUILDER-R011.2` | **Deterministic output.** The generator must write byte-identical files for the same fleet name and write no date, user or host name. | `tests/test_mcp_builder_connector_scaffold.py::test_generation_is_deterministic` passes. |
| `US-MCP-BUILDER-R011.3` | **Identity and version in pyproject only.** The generated `pyproject.toml` must hold the version, the one `agent_connector_sdk.connector` entry point, the `agent_connector_sdk.cli:serve` console script and the floor `agent-connector-sdk[mcp]>=0.5.0,<1.0.0`. No Python file may spell the version or the fleet name. Requires agent-connector-sdk 0.5.0 to start the server. | `tests/test_mcp_builder_connector_scaffold.py::test_identity_and_version_live_in_pyproject_only` passes. |
| `US-MCP-BUILDER-R011.4` | **Shared workflows for release and PR.** The generated workflows must call the shared pipelines `python_pipeline.yml`, `container_pipeline.yml` and `connector_pr_pipeline.yml` at `main`, publishing to PyPI and Docker Hub. | `tests/test_mcp_builder_connector_scaffold.py::test_workflows_call_the_shared_pipelines_for_pypi_and_docker` passes. |
| `US-MCP-BUILDER-R011.5` | **One tool per operation with risk classes.** The generated `tools.py` must register each API operation as its own tool, with read, write and destructive annotations. No tool may take an `action` or `params_json` argument. | `tests/test_mcp_builder_connector_scaffold.py::test_one_tool_per_operation_with_risk_annotations` passes. |
| `US-MCP-BUILDER-R011.6` | **Sources declared in tool metadata.** A read tool must declare its data source with `source_meta`. The scaffold must write no manifest file; the SDK serves the declaration as `connector://resources`. | `tests/test_mcp_builder_connector_scaffold.py::test_sources_are_declared_in_tool_meta_and_no_manifest_file_exists` passes. |
| `US-MCP-BUILDER-R011.7` | **Content served over MCP.** The generated prompt must be a fastmcp prompt with a title and metadata. The generated skill directory and ontology must be served as skill and ontology resources. The scaffold must write no file that is served separately. | `tests/test_mcp_builder_connector_scaffold.py::test_prompt_skill_and_ontology_are_served_over_mcp` passes. |
| `US-MCP-BUILDER-R011.8` | **Ontology rolls up to a core class.** Every generated class must extend a core class of the parent ontology with `rdfs:subClassOf`. The pack must not use `owl:imports` for the parent ontology. | `tests/test_mcp_builder_connector_scaffold.py::test_ontology_rolls_up_to_a_core_class_and_never_imports_the_parent` passes. |
| `US-MCP-BUILDER-R011.9` | **Pipelines connector gates pass.** The generated repository must pass the pipelines `connector-name` and `release-standard` gates in strict mode. | `tests/test_mcp_builder_connector_scaffold.py::test_pipelines_connector_gates_pass` passes. |
| `US-MCP-BUILDER-R011.10` | **Ontology graph check passes.** The generated pack must raise no `connector-ontology-map graph-check` finding against the parent ontology. The test needs `EPISTEMIC_GRAPH_REPO`. | `tests/test_mcp_builder_connector_scaffold.py::test_ontology_graph_check_passes_against_the_core_ontology` passes. |
| `US-MCP-BUILDER-R011.11` | **SDK conformance plugin passes.** The generated package must pass the SDK pytest conformance plugin and hold no copy of its tests. Requires agent-connector-sdk 0.5.0; the test skips below it. | `tests/test_mcp_builder_connector_scaffold.py::test_generated_package_passes_the_sdk_conformance_plugin` passes. |
