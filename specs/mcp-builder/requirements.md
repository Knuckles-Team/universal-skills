# US-MCP-BUILDER — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `US-MCP-BUILDER-R011` | **Connector scaffold on SDK components.** `scripts/scaffold_connector.py` must be the only connector generator. It must emit only connector-specific files and build the connector on SDK components. Parent of R011.1 to R011.13. SDK owners: `SCION-CONNECTOR-CONTROL-R019.1`, `SCION-QUALITY-RELEASE-R005.1`. | Every child row passes. |
| `US-MCP-BUILDER-R011.1` | **Exact connector-owned tree.** The generator must write exactly the 26 files of the minimal connector tree: the package/API/content/spec files plus the aggregate hook reference, dashboard config, release/PR/Pages callers, `pages/index.md`, and the repository development skill. It must write none of the files the SDK or pipelines own: no `mcp_server.py`, `tools.py`, `_version.py`, `.bumpversion.cfg`, `docker/` files, `certification.json`, shapes file, `mcp_config.json`, `conftest.py`, `kg_ingest.py`, or shared-theme assets. The Pages caller leaves `shared_theme_enabled` false until a pinned pipelines checkout generates canonical theme outputs with `scripts/sync_mkdocs_theme.py`. | `tests/test_mcp_builder_connector_scaffold.py::test_scaffold_emits_exactly_the_minimal_tree` and `tests/test_mcp_builder_connector_scaffold.py::test_generated_pages_caller_has_a_safe_shared_theme_preflight` pass. |
| `US-MCP-BUILDER-R011.2` | **Deterministic output.** The generator must write byte-identical files for the same fleet name. It must write no date, user or host name. | `tests/test_mcp_builder_connector_scaffold.py::test_generation_is_deterministic` passes. |
| `US-MCP-BUILDER-R011.3` | **Identity and version in pyproject only.** The generated `pyproject.toml` must hold the version, the one `agent_connector_sdk.connector` entry point `<fleet> = "<pkg>:connector"`, the `agent_connector_sdk.cli:serve` console script and the floor `agent-connector-sdk[mcp]>=0.5.1,<0.6`. No Python file may spell the version or the fleet name. | `tests/test_mcp_builder_connector_scaffold.py::test_identity_and_version_live_in_pyproject_only` passes. |
| `US-MCP-BUILDER-R011.4` | **Shared workflows for release and PR.** The release workflow must call the shared `python_pipeline.yml` with `connector: true` and `container_pipeline.yml` with `render_connector: true`, publishing to PyPI and Docker Hub. The PR workflow must call `connector_pr_pipeline.yml`. | `tests/test_mcp_builder_connector_scaffold.py::test_workflows_call_the_shared_pipelines_for_pypi_and_docker` passes. |
| `US-MCP-BUILDER-R011.5` | **One tool per operation with risk classes.** The generated `Api` class must hold one public method per API operation, and the SDK must serve one tool per method. Read, write and destructive annotations must follow the verb. No tool may take an `action` or `params_json` argument. | `tests/test_mcp_builder_connector_scaffold.py::test_one_tool_per_operation_with_risk_annotations` passes. |
| `US-MCP-BUILDER-R011.6` | **Sources declared as data.** `connector_sources.py` must declare each source with `source_meta(tool=...)`. The SDK must load it with `load_declaration` and serve it as `connector://resources`. The scaffold must write no manifest file and no `declaration()` function. | `tests/test_mcp_builder_connector_scaffold.py::test_sources_load_as_typed_declaration_with_no_manifest_file` passes. |
| `US-MCP-BUILDER-R011.7` | **Content served over MCP.** The generated prompt must be a fastmcp prompt with a title and metadata. The generated skill and ontology must be served as resources. The scaffold must write no file that is served separately. | `tests/test_mcp_builder_connector_scaffold.py::test_prompt_skill_and_ontology_are_served_over_mcp` passes. |
| `US-MCP-BUILDER-R011.8` | **Ontology rolls up to a core class.** Every generated class must extend a core class of the parent ontology with `rdfs:subClassOf`. The pack must not use `owl:imports` for the parent ontology. | `tests/test_mcp_builder_connector_scaffold.py::test_ontology_rolls_up_to_a_core_class_and_never_imports_the_parent` passes. |
| `US-MCP-BUILDER-R011.9` | **Pipelines connector gates pass.** The generated repository must pass the pipelines `connector-name` gate in strict mode and the `connector-standard` file and spelling checks. | `tests/test_mcp_builder_connector_scaffold.py::test_pipelines_connector_gates_pass` passes. |
| `US-MCP-BUILDER-R011.10` | **Ontology graph check passes.** The generated pack must raise no `connector-ontology-map graph-check` finding against the core ontology at the revision pinned in the test. The test fetches that revision; it needs no local checkout. | `tests/test_mcp_builder_connector_scaffold.py::test_ontology_graph_check_passes_against_the_core_ontology` passes. |
| `US-MCP-BUILDER-R011.11` | **SDK conformance plugin passes.** The generated package must pass the SDK pytest conformance plugin and hold no copy of its tests. | `tests/test_mcp_builder_connector_scaffold.py::test_generated_package_passes_the_sdk_conformance_plugin` passes. |
| `US-MCP-BUILDER-R011.12` | **Client from one SDK auth declaration.** `auth.py` must build the client with `client_factory` and one auth declaration, a TLS profile name and delegation. No generated module may import `requests` or `httpx`, disable TLS verification, build an SSL context or hold a thread-local token. SDK owner: `SCION-CONNECTOR-CONTROL-R028.4`. | `tests/test_mcp_builder_connector_scaffold.py::test_client_is_one_sdk_auth_declaration_with_no_own_transport` passes. |
| `US-MCP-BUILDER-R011.13` | **Dependencies through SDK extras.** The generated `pyproject.toml` must depend on the SDK only, declare no optional dependency and declare no entry point other than the connector identity. A connector adds optional dependencies as SDK extras. | `tests/test_mcp_builder_connector_scaffold.py::test_optional_dependencies_are_sdk_extras_only` passes. |
