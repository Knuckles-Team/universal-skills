# US-CONTENT requirements

Every requirement this specification owns, with the proof that closes it. Delivery state and evidence for each ID are recorded in `status.json`; this file defines what each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md), the test contract in [`test-spec.md`](test-spec.md), and the work order in [`tasks.md`](tasks.md).

| ID | Requirement | Verification |
|---|---|---|
| `US-CONTENT-R001` | **`universal_skills` is served as a content-only connector.** The package declares exactly one entry point, `agent_connector_sdk.connector = "universal_skills"`, and no provider entry-point group. Children `.1` to `.3` deliver it. | See each child. |
| `US-CONTENT-R001.1` | `pyproject.toml` declares `[project.entry-points."agent_connector_sdk.connector"]` with the single value `universal_skills` (bare package, content only), depends on `agent-connector-sdk[mcp]>=0.5.0,<0.6.0`, and declares no `agent_utilities.skill_providers` or other provider group. The SDK pytest plugin supplies the conformance checks, so the repository holds no copy of them. Proving test: `tests/test_catalog_content.py::test_declares_one_content_only_entry_point`. | The test reads `pyproject.toml` and finds one entry point of the group, the bare package, the SDK floor and cap, and no provider group. |
| `US-CONTENT-R001.2` | Every skill lives at `universal_skills/skills/<name>/SKILL.md`, one level deep, and its frontmatter `name` equals its folder name. Supporting files stay inside the skill folder so they are served with it. Proving test: `tests/test_catalog_content.py::test_every_skill_is_flat_and_named_by_folder`. | The test finds no `SKILL.md` outside `skills/<name>/` (other than bundled assets) and no name that differs from its folder. |
| `US-CONTENT-R001.3` | The server the SDK builds for `universal_skills` lists one `skill://<name>/SKILL.md` resource for every skill folder. Proving test: `tests/test_catalog_content.py::test_server_lists_every_skill`. | The test builds the server in process and compares the listed skill names with the folders. |
| `US-CONTENT-R002` | **Skills can be vendored from pinned upstream repositories and kept current.** The repository holds `upstream-sources.toml` and `scripts/sync_upstream_skills.py`. Children `.1` to `.10` deliver it. | See each child. |
| `US-CONTENT-R002.1` | `upstream-sources.toml` lists each source with its repository URL, a pinned commit, path globs, the skills it produces, the license and a transform (`skill-md` or `command-md`). The loader rejects a manifest that omits one of them, that names a skill whose path matches no glob, or that has a duplicate source or skill. Proving test: `tests/test_upstream_sources.py::test_manifest_rejects_incomplete_sources`. | The test loads the real manifest and a set of broken manifests and finds the loader accepts the first and rejects each of the others. |
| `US-CONTENT-R002.2` | A pin is a full 40-character commit SHA. A branch, tag or short SHA is rejected. `--update` is the only way a pin moves. Proving test: `tests/test_upstream_sources.py::test_pin_must_be_full_commit_sha`. | The test loads manifests with a branch name, a tag and a short SHA and finds each rejected. |
| `US-CONTENT-R002.3` | Each vendored skill keeps the upstream license text in `LICENSE` and names the license in its provenance file. A source without a license or license path is rejected. Proving test: `tests/test_upstream_sources.py::test_license_is_required_and_kept`. | The test finds the loader rejecting a source with no license and each real vendored skill holding the upstream license text. |
| `US-CONTENT-R002.4` | The `skill-md` transform copies a skill folder as it is and sets only `metadata.version` from this package. The `command-md` transform converts a command prompt into a `SKILL.md` with `name`, `description` and the package version, resolves the script and command placeholders, and drops the upstream handoff and script keys. Both produce identical bytes on every run. Proving test: `tests/test_upstream_sources.py::test_transforms_are_deterministic`. | The test renders each transform twice from one input and finds identical bytes and the expected frontmatter. |
| `US-CONTENT-R002.5` | Overlays in `universal_skills/overlays/<skill>/*.md` merge into the rendered skill in file-name order with the modes `append`, `prepend`, `replace`, `insert-after` and `file`. A `replace` or `insert-after` whose match does not hit exactly one line fails. Proving test: `tests/test_upstream_sources.py::test_overlay_merge_is_ordered_and_strict`. | The test applies each mode, finds the expected text and finds the ambiguous match rejected. |
| `US-CONTENT-R002.6` | A sync fetches the pin into a throwaway repository, reads files from the git object store, executes none of them, and writes the snapshot under `universal_skills/upstream/<source>/`, the skill folder, `LICENSE` and `UPSTREAM.md` (source URL, pinned commit, path, license, transform, sync date, source digest, overlay list). Proving test: `tests/test_upstream_sources.py::test_sync_writes_provenance_without_running_code`. | The test syncs from a local repository holding an executable script and finds the provenance fields, the license and no sign the script ran. |
| `US-CONTENT-R002.7` | `--check` runs offline and fails when any vendored file differs from the pinned snapshot plus overlays, when a file is missing or extra, or (with `--verify-pin`) when the snapshot differs from upstream. Proving test: `tests/test_upstream_sources.py::test_check_detects_hand_edits_and_overlay_drift`. | The test finds a clean tree passing, then a hand edit, an extra file and an overlay change each reported as drift. |
| `US-CONTENT-R002.8` | `--update <source>` moves the pin to the latest commit of the source's tracked branch, keeps the manifest comments, and re-syncs so the change is one reviewable diff. Proving test: `tests/test_upstream_sources.py::test_update_moves_the_pin_and_resyncs`. | The test updates a local source after a new upstream commit and finds the new pin, the kept comment and the new skill text. |
| `US-CONTENT-R002.9` | The spec-kit source vendors `speckit-constitution`, `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks`, `speckit-analyze`, `speckit-checklist` and `speckit-implement`, each with an overlay that carries the repository extensions. The skills `spec-generator`, `task-planner`, `spec-verifier`, `spec-intake-wizard` and `feature-development-pipeline` are removed and no file in the repository refers to them. Proving test: `tests/test_upstream_sources.py::test_spec_kit_skills_replace_the_retired_skills`. | The test finds the eight skills in sync with their pins, the five retired folders absent and no reference left. |
| `US-CONTENT-R002.10` | The pre-commit configuration runs `scripts/sync_upstream_skills.py --check`, and the `universal-installer` skill describes the update procedure: `--update` per source, `--check --verify-pin`, the tests, then a pull request and never a push to the default branch. Proving test: `tests/test_upstream_sources.py::test_hook_and_installer_are_wired`. | The test finds the hook entry and the procedure in the installer skill. |
