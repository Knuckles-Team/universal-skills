# US-CONTENT requirements

Every requirement this specification owns, with the proof that closes it. Delivery state and evidence for each ID are recorded in `status.json`; this file defines what each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md), the test contract in [`test-spec.md`](test-spec.md), and the work order in [`tasks.md`](tasks.md).

| ID | Requirement | Verification |
|---|---|---|
| `US-CONTENT-R001` | **`universal_skills` is served as a content-only connector.** The package declares exactly one entry point, `agent_connector_sdk.connector = "universal_skills"`, and no provider entry-point group. Children `.1` to `.3` deliver it. | See each child. |
| `US-CONTENT-R001.1` | `pyproject.toml` declares `[project.entry-points."agent_connector_sdk.connector"]` with the single value `universal_skills` (bare package, content only), depends on `agent-connector-sdk[mcp]>=0.5.0,<0.6.0`, and declares no `agent_utilities.skill_providers` or other provider group. The SDK pytest plugin supplies the conformance checks, so the repository holds no copy of them. Caller chain: arbora resolves the installed distribution → the `agent_connector_sdk.connector` entry point of `pyproject.toml`. Shape: one entry-point table in `pyproject.toml`; the SDK pytest plugin supplies the checks. Proving test: `tests/test_catalog_content.py::test_declares_one_content_only_entry_point`. | The test reads `pyproject.toml` and finds one entry point of the group, the bare package, the SDK floor and cap, and no provider group. |
| `US-CONTENT-R001.2` | Every skill lives at `universal_skills/skills/<name>/SKILL.md`, one level deep, and its frontmatter `name` equals its folder name. Supporting files stay inside the skill folder so they are served with it. Caller chain: the SDK content convention → `universal_skills/skills/<name>/SKILL.md`. Shape: flat skill folders; the test reuses `tests/test_catalog_content.py` helpers. Proving test: `tests/test_catalog_content.py::test_every_skill_is_flat_and_named_by_folder`. | The test finds no `SKILL.md` outside `skills/<name>/` (other than bundled assets) and no name that differs from its folder. |
| `US-CONTENT-R001.3` | The server the SDK builds for `universal_skills` lists one `skill://<name>/SKILL.md` resource for every skill folder. Caller chain: arbora → the SDK server factory → the skills directory provider → each skill folder. Shape: no server code in this package; the test builds the SDK server in process. Proving test: `tests/test_catalog_content.py::test_server_lists_every_skill`. | The test builds the server in process and compares the listed skill names with the folders. |
| `US-CONTENT-R002` | **Skills can be vendored from pinned upstream repositories and kept current.** The repository holds `upstream-sources.toml` and `scripts/sync_upstream_skills.py`. Children `.1` to `.10` deliver it. | See each child. |
| `US-CONTENT-R002.1` | `upstream-sources.toml` lists each source with its repository URL, a pinned commit, path globs, the skills it produces, the license and a transform (`skill-md` or `command-md`). The loader rejects a manifest that omits one of them, that names a skill whose path matches no glob, or that has a duplicate source or skill. Caller chain: `scripts/sync_upstream_skills.py` → its manifest loader → `upstream-sources.toml`. Shape: one loader function in `scripts/sync_upstream_skills.py` that validates each source table. Proving test: `tests/test_upstream_sources.py::test_manifest_rejects_incomplete_sources`. | The test loads the real manifest and a set of broken manifests and finds the loader accepts the first and rejects each of the others. |
| `US-CONTENT-R002.2` | A pin is a full 40-character commit SHA. A branch, tag or short SHA is rejected. `--update` is the only way a pin moves. Caller chain: `scripts/sync_upstream_skills.py` → the manifest loader → the pin check. Shape: a pin check in the loader of `scripts/sync_upstream_skills.py`. Proving test: `tests/test_upstream_sources.py::test_pin_must_be_full_commit_sha`. | The test loads manifests with a branch name, a tag and a short SHA and finds each rejected. |
| `US-CONTENT-R002.3` | Each vendored skill keeps the upstream license text in `LICENSE` and names the license in its provenance file. A source without a license or license path is rejected. Caller chain: `scripts/sync_upstream_skills.py` → the license copy step → the skill folder. Shape: the license copy in `scripts/sync_upstream_skills.py`, reusing the snapshot reader. Proving test: `tests/test_upstream_sources.py::test_license_is_required_and_kept`. | The test finds the loader rejecting a source with no license and each real vendored skill holding the upstream license text. |
| `US-CONTENT-R002.4` | The `skill-md` transform copies a skill folder as it is and sets only `metadata.version` from this package. The `command-md` transform converts a command prompt into a `SKILL.md` with `name`, `description` and the package version, resolves the script and command placeholders, and drops the upstream handoff and script keys. Both produce identical bytes on every run. Caller chain: `scripts/sync_upstream_skills.py` → the transform named by the source → the rendered `SKILL.md`. Shape: two transform functions in `scripts/sync_upstream_skills.py`. Proving test: `tests/test_upstream_sources.py::test_transforms_are_deterministic`. | The test renders each transform twice from one input and finds identical bytes and the expected frontmatter. |
| `US-CONTENT-R002.5` | Overlays in `universal_skills/overlays/<skill>/*.md` merge into the rendered skill in file-name order with the modes `append`, `prepend`, `replace`, `insert-after` and `file`. A `replace` or `insert-after` whose match does not hit exactly one line fails. Caller chain: `scripts/sync_upstream_skills.py` → the overlay merge after the render → `universal_skills/overlays/<skill>/*.md`. Shape: one merge function in `scripts/sync_upstream_skills.py`. Proving test: `tests/test_upstream_sources.py::test_overlay_merge_is_ordered_and_strict`. | The test applies each mode, finds the expected text and finds the ambiguous match rejected. |
| `US-CONTENT-R002.6` | A sync fetches the pin into a throwaway repository, reads files from the git object store, executes none of them, and writes the snapshot under `universal_skills/upstream/<source>/`, the skill folder, `LICENSE` and `UPSTREAM.md` (source URL, pinned commit, path, license, transform, sync date, source digest, overlay list). Caller chain: `scripts/sync_upstream_skills.py` → the fetch into a throwaway repository → the snapshot writer. Shape: the sync command in `scripts/sync_upstream_skills.py`, reading blobs with `git cat-file`. Proving test: `tests/test_upstream_sources.py::test_sync_writes_provenance_without_running_code`. | The test syncs from a local repository holding an executable script and finds the provenance fields, the license and no sign the script ran. |
| `US-CONTENT-R002.7` | `--check` runs offline and fails when any vendored file differs from the pinned snapshot plus overlays, when a file is missing or extra, or (with `--verify-pin`) when the snapshot differs from upstream. Caller chain: the pre-commit hook → `scripts/sync_upstream_skills.py --check` → the drift comparison. Shape: the check mode of `scripts/sync_upstream_skills.py`, reusing the render and merge functions. Proving test: `tests/test_upstream_sources.py::test_check_detects_hand_edits_and_overlay_drift`. | The test finds a clean tree passing, then a hand edit, an extra file and an overlay change each reported as drift. |
| `US-CONTENT-R002.8` | `--update <source>` moves the pin to the latest commit of the source's tracked branch, keeps the manifest comments, and re-syncs so the change is one reviewable diff. Caller chain: a maintainer → `scripts/sync_upstream_skills.py --update <source>` → the pin rewrite and the re-sync. Shape: the update mode of `scripts/sync_upstream_skills.py`, reusing the sync command. Proving test: `tests/test_upstream_sources.py::test_update_moves_the_pin_and_resyncs`. | The test updates a local source after a new upstream commit and finds the new pin, the kept comment and the new skill text. |
| `US-CONTENT-R002.9` | The spec-kit source vendors `speckit-constitution`, `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks`, `speckit-analyze`, `speckit-checklist` and `speckit-implement`, each with an overlay that carries the repository extensions. The skills `spec-generator`, `task-planner`, `spec-verifier`, `spec-intake-wizard` and `feature-development-pipeline` are removed and no file in the repository refers to them. Caller chain: `scripts/sync_upstream_skills.py` → the spec-kit source of `upstream-sources.toml` → eight skill folders. Shape: one source table in `upstream-sources.toml` and one overlay folder per skill. Proving test: `tests/test_upstream_sources.py::test_spec_kit_skills_replace_the_retired_skills`. | The test finds the eight skills in sync with their pins, the five retired folders absent and no reference left. |
| `US-CONTENT-R002.10` | The pre-commit configuration runs `scripts/sync_upstream_skills.py --check`, and the `universal-installer` skill describes the update procedure: `--update` per source, `--check --verify-pin`, the tests, then a pull request and never a push to the default branch. Caller chain: the pre-commit configuration → `scripts/sync_upstream_skills.py --check`. Shape: one hook entry in the pre-commit configuration and one procedure section in the `universal-installer` skill. Proving test: `tests/test_upstream_sources.py::test_hook_and_installer_are_wired`. | The test finds the hook entry and the procedure in the installer skill. |
| `US-CONTENT-R003` | **The `code-enhancer` skill follows the organization constitution.** Its scripts take size, complexity and clone limits from one module that mirrors the constitution thresholds table. It has no baseline or ratchet mode. It writes specs to `specs/<feature>/`. It names only current intent tools of the graph door. It carries no legacy concept IDs in its examples. Its dependency guidance points at article XXVII. Caller chain: a maintainer runs the `code-enhancer` skill scripts → its limits module. Shape: one limits module under `universal_skills/skills/code-enhancer/` that mirrors the constitution table. Proving test: `tests/test_code_enhancer.py::test_code_enhancer_follows_the_organization_constitution`. | The test finds the limits module holding the table values, no baseline script or flag, no `.specify` output path, no retired tool or package name, no legacy concept ID, and the article reference in the skill. |
| `US-CONTENT-R004` | **The `spec-row-delivery` skill guides one delivery assignment run (rollup).** The catalog holds one skill that states the procedure for delivering one spec row as one change proposal. A delivery assignment run of meristem loads it (`MERISTEM-SCM-R012`). The run reports to the engine delivery records (`MEDULLA-SDLC-R019.7`). The skill holds procedure only; it decides nothing and calls no tool by itself. Children `.1` to `.3` deliver it. Depends on: US-CONTENT-R001.2. | Satisfied only when every child is satisfied. Root test: `tests/test_spec_row_delivery_skill.py::test_skill_states_the_full_delivery_procedure`. |
| `US-CONTENT-R004.1` | **Content: the delivery procedure.** `universal_skills/skills/spec-row-delivery/SKILL.md` must state these steps in order. Read the row, its plan section and its contracts. Search the existing code before writing new code. Implement the row with a test bound to its ID. Commit with the `Spec:` trailer directly above the co-author line. Run the gates the change touches. End with one report state: `progress`, `waiting`, `ready`, `blocked`, `failed` or `dropped`. Resolve a review thread when its finding is fixed. Post one reply with a reason when a suggestion is declined. Stop work on an automated reviewer after a received `stop_addressing` verdict. The skill must forbid a merge, an auto-merge arming, a spec edit and a skipped gate. Caller chain: meristem delivery assignment run (`MERISTEM-SCM-R012.2`) → skill resource `skill://spec-row-delivery/SKILL.md` served by the SDK content convention (US-CONTENT-R001.3). Shape: one new `SKILL.md` in the flat layout of US-CONTENT-R001.2; no script and no server code. Refusal: the validation test fails and names the missing step or the missing prohibition. Knob: none. Depends on: US-CONTENT-R001.2, MERISTEM-SCM-R012. | Test: `tests/test_spec_row_delivery_skill.py::test_skill_states_the_full_delivery_procedure`. |
| `US-CONTENT-R004.2` | **Frontmatter and catalog registration.** The skill frontmatter must carry `name: spec-row-delivery`, a one-sentence `description` with its trigger, `domain: development` and `skill_type: skill`. Its `metadata.version` must equal the package version. The served catalog must list `skill://spec-row-delivery/SKILL.md`. The skill must pass the hooks `check-atomicity`, `check-frontmatter-portability` and `skill-catalog-structure`. Caller chain: arbora serves the catalog → the SDK content convention (US-CONTENT-R001.3) → the skill folder. Shape: frontmatter keys in the style of `universal_skills/skills/sdd-implementer/SKILL.md`; reuse `tests/test_catalog_content.py::test_server_lists_every_skill` for the listing. Refusal: a portability or atomicity hook failure blocks the commit. Knob: none. Depends on: US-CONTENT-R004.1, US-CONTENT-R001.3. | Test: `tests/test_spec_row_delivery_skill.py::test_frontmatter_is_portable_and_the_catalog_lists_the_skill`. |
| `US-CONTENT-R004.3` | **Validation test: procedure, prohibitions and neutral text.** New `tests/test_spec_row_delivery_skill.py` must read the skill text. It asserts each step of US-CONTENT-R004.1 in order and each of the four prohibitions. It also asserts that the text names no host, private domain or local path. Caller chain: `pytest` → `tests/test_spec_row_delivery_skill.py` → `universal_skills/skills/spec-row-delivery/SKILL.md`. Shape: one test module that reuses the skill-path helpers of `tests/test_catalog_content.py`. Refusal: a missing step, a missing prohibition or a private name fails the test. Knob: none. Depends on: US-CONTENT-R004.1, US-CONTENT-R004.2. | Test: `tests/test_spec_row_delivery_skill.py::test_skill_text_is_neutral_and_forbids_merge_and_skips`. |
